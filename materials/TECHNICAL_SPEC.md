# SMART TRAFFIC LAB — полное техническое задание

## 1. Паспорт проекта

Название: SMART TRAFFIC LAB — Ақылды қаланың математикалық зертханасы. Тема исследования: «Ақылды қала жағдайында жол қозғалысын тиімді басқарудың математикалық модельдері». Ученик: Қадырбек Жанель Әділханқызы, 7 «А» класс. Руководитель: Ашимханова Фаруза Турсынбековна. Формат: адаптивное веб-приложение, основной язык — казахский. Цель — создать воспроизводимую компьютерную модель дорожного движения для проверки гипотезы об эффективности адаптивного управления. Продукт является учебным симулятором, а не системой управления реальными дорогами.

## 2. Исходные материалы и ограничения

Источник: предоставленный PDF научного проекта, 39 страниц. Сохранить тему, термины, формулы q=ρ·v, граф A–B–C–D, два режима светофоров, сравнение ожидания и исследовательскую логику. Таблица рёбер (расстояние км / скорость км/ч / время мин): AB 2/40/3; AC 3/30/6; BD 4/40/6; CD 2/20/6; BC 1/20/3; AD 5/50/6. Значения — учебный набор, а не геопривязанные дорожные измерения. Сценарии потока: ρ=40, v=50, q=2000; ρ=80, v=30, q=2400; ρ=120, v=15, q=1800. Время ожидания по трём условным перекрёсткам: фиксированное 60,55,70 секунд; адаптивное 35,30,40 секунд. Это исходные примеры, не результат будущего движка. Статистические утверждения исходного PDF автоматически не переносить в выводы: для таблицы [[1,2],[3,0]] χ² Пирсона=3, p≈0,083; малые ожидаемые частоты требуют иного метода. Ссылки на источники, реальные координаты и полевые наблюдения подтверждать отдельно.

## 3. Пользовательские сценарии

Ученик открывает демонстрацию, выбирает дорожную сеть и интенсивность, наблюдает движение машин, сравнивает режимы и получает график. Исследователь меняет параметры, фиксирует seed, запускает N повторов и выгружает таблицу. Учитель показывает эксперименты на проекторе и объясняет формулы. Эксперт защиты может самостоятельно повторить сохранённый эксперимент по идентификатору сценария. Администратор может импортировать проверенные CSV-наблюдения с пометкой источника.

## 4. Навигация и дизайн

Маршруты: /, /city, /signals, /models, /routes, /experiments, /statistics, /assistant, /reports, /about. Интерфейс на казахском: Басты бет, Ақылды қала, Бағдаршам зертханасы, Математикалық модельдер, Маршрут зертханасы, Тәжірибелер, Статистика, AI зерттеуші, Ғылыми есеп, Жоба туралы. Белый фон, графитовый текст, сдержанные синие/бирюзовые акценты, светофорные красный-жёлтый-зелёный только по смыслу. Контраст WCAG AA, клавиатурное управление, адаптация 360–1920 px. Карта — Canvas/SVG с ясными дорогами, полосами, пешеходными переходами, движущимися машинами и фазами; не выдавать условную схему за настоящую карту Меркі.

## 5. Архитектура

Рекомендуемый стек: React + TypeScript + Vite; Tailwind CSS; SVG/Canvas для симуляции; Recharts для графиков; Web Worker для расчётного ядра; Zustand или Redux для состояния; jsPDF либо pdf-lib для отчётов; CSV экспорт без сервера. Деплой Vercel. Для MVP не требуются SQL, авторизация и платные API. Расчётное ядро отделить от UI, чтобы можно было тестировать без браузера. Псевдослучайный генератор с фиксируемым seed; сохранять версию модели и параметры. AI-модуль опциональный, без API-ключа — локальные объяснения на основе правил; никакой имитации вызова настоящей нейросети.

## 6. Модель движения

Дискретно-событийная или пошаговая микросимуляция с шагом Δt=0,2–1 сек (настройка). Сущности: RoadSegment(id,length,lanes,speedLimit,capacity), Junction(id,phases), Vehicle(id,origin,destination,route,position,speed,arrivalTime,waitTime), Signal(phase,state,timer), Scenario(seed,duration,demand). Генерация машин по заданной интенсивности с опциональной моделью Пуассона; допустим импорт фактических временных рядов. На каждой итерации: сгенерировать прибытия, обновить фазу светофора, определить допустимое продвижение без наложения машин, продвинуть автомобили, обновить очереди, задержки и выходы. Должны быть ограничения дистанции, скорости, пропускной способности и невозможности проезда на запрещающий сигнал. Отдельно определить движение по направлениям и повороты. Отображение симуляции должно брать координаты из ядра, а не создавать декоративное движение.

## 7. Два алгоритма светофора

Фиксированный: конфигурируемый цикл, например 30 сек зелёного, 3 сек жёлтого, безопасный межфазный интервал и соответствующий красный для конфликтующего направления. Адаптивный: для каждой совместимой фазы i вычислять S_i=N_i+α·W_i, где N_i — число автомобилей в очереди, W_i — среднее ожидание, α — явно задаваемый коэффициент в согласованных единицах. Выбирать фазу с наибольшим S_i с ограничениями minGreen=10 с, maxGreen=60 с, maxRed=120 с, yellow=3 с и allRed=1 с (все числа — учебные настройки, не нормативы). Нельзя одновременно давать зелёный конфликтующим направлениям. Гарантировать обслуживание малонагруженных направлений, чтобы не возникало голодания. Алгоритм не объявлять оптимальным без проверки.

## 8. Математика и маршруты

q=ρ·v с контролем единиц и указанием числа полос. Для модели скорость–плотность дать редактируемую гипотезу v(ρ)=v_free·max(0,1−ρ/ρ_jam), не подменять ей наблюдения. Граф A,B,C,D, 6 рёбер с исходными значениями. Алгоритм Дейкстры: режим минимальной длины и минимального времени, поэтапная подсветка узлов, проверка неотрицательных весов. Показать альтернативные маршруты и то, что кратчайший по длине не обязательно самый быстрый. При динамических весах пересчитывать путь после обновления стоимости, документировать момент перерасчёта.

## 9. Десять экспериментов

E01 интенсивность 100/300/600/900 авт./час на направление; E02 фиксированный против адаптивного при одинаковом seed; E03 длительность зелёного 15/30/45/60 с; E04 утренний пик с повышенным потоком; E05 асимметрия потоков 80/20; E06 маршрут минимальной длины; E07 маршрут минимального времени; E08 стресс-тест близко к пропускной способности; E09 транзитный поток грузовых автомобилей с пониженной скоростью; E10 30+ повторов с несколькими seed и статистическим анализом. Указанные интенсивности — стартовые тестовые параметры, их нужно калибровать. Каждый эксперимент сохраняет параметры, seed, версию алгоритма, длительность, число машин, время ожидания, очереди, throughput, доверительные интервалы при допустимости.

## 10. Метрики и статистика

Среднее ожидание = сумма времени неподвижности/число завершивших поездку (отдельно показывать незавершившие поездки). Средняя длина очереди — усреднение по времени; максимум очереди — пик; throughput — число завершивших проезд за час модельного времени; средняя длительность поездки — по завершившим. Сравнение режимов только на одинаковом спросе и одинаковом seed. Процент улучшения ожидания: (W_fixed−W_adaptive)/W_fixed·100% при W_fixed>0. Экспортировать все повторы, не только средние. Использовать парные разности по seed, доверительные интервалы, прозрачную проверку допущений; при малых частотах не использовать χ² Пирсона как окончательное доказательство. Нельзя автоматически писать «статистически доказано», если критерий не пройден.

## 11. Экран эксперимента

Слева: выбор сценария, генератор потока, длительность, seed, скорость воспроизведения, режим управления, кнопки Іске қосу/Тоқтату/Қайта бастау. Центр: 2D/изометрическая карта с очередями и светофорами. Справа: живые KPI, число ожидающих, среднее ожидание, пройденные автомобили. Снизу: графики очереди по времени, сравнительная гистограмма и журнал событий. Режим сравнения должен запускать два независимых ядра с одинаковыми входными событиями, а не копировать готовые числа.

## 12. AI зерттеуші

Опциональная панель с вопросами «Неліктен кептеліс пайда болды?», «Қай модель тиімді?», «Формула нені білдіреді?». Без подключённого LLM отвечать локальным проверяемым шаблоном на основе вычисленных метрик, прямо помечая «Ережеге негізделген түсіндірме». При наличии внешнего LLM — отдельный серверный endpoint, секреты только на сервере, лимиты запросов, защита персональных данных; не выдавать генеративный ответ за численный расчёт. Модель не должна сочинять статистическую значимость.

## 13. Научный отчёт и экспорт

PDF на казахском с заголовком, датой, версией алгоритма, seed, исходными параметрами, методикой, таблицами, графиками, числом повторов, ограничениями и заключением без неподтверждённых утверждений. CSV с сырыми измерениями и агрегатами; JSON сценария для повторного запуска. Корректные казахские символы в PDF, A4, читабельные таблицы и графики. QR-код только после публикации действующей ссылки. Не включать в отчёт личные данные без необходимости.

## 14. Данные, безопасность и доступность

Демо работает полностью офлайн после загрузки ресурсов (по возможности PWA). Вводимые данные проверять: неотрицательные скорости, плотности, интенсивности; разумные ограничения количества автомобилей и длительности симуляции; безопасное завершение при перегрузке. Данные в localStorage/IndexedDB, кнопка очистки, экспорт/импорт JSON с проверкой схемы. Отсутствие рекламы, трекеров и скрытых внешних запросов. Никаких реальных управляющих команд дорожной инфраструктуре.

## 15. Критерии приёмки

1) При одинаковом seed и настройках воспроизводятся одинаковые результаты. 2) Машины не пересекают конфликтующие направления на зелёный одновременно. 3) Смена режима действительно меняет алгоритм и результаты при подходящем сценарии. 4) Изменение интенсивности меняет поступление машин и метрики. 5) Дейкстра возвращает проверяемые пути для графа A–D. 6) Формула q=ρv проверена unit-тестами. 7) Сравнение использует идентичный спрос. 8) Нет зашитых в KPI значений 61,7 и 35 с. 9) Отчёт PDF открывается и содержит кириллицу/қазақша. 10) CSV импортируется в Excel. 11) Работает на Android Chrome и desktop Chrome/Edge. 12) Нет ошибок в консоли, отсутствуют битые ссылки. 13) Проект собирается npm install && npm run build. 14) Исходный код, README, тесты и конфигурация в архиве.
